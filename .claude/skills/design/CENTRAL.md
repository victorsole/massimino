# Central designs file: `docs/marketing/designs/index.html`

This file accumulates EVERY /design output as one section per design, newest at the top. Treat it as a reusable template library.

**Git status:** `docs/` is not gitignored in this repo. Before the first run, ask Victor whether the design library (and its exported PNGs, which get large) should be ignored. If he says yes, add:

```
# /design output (local design library, export source)
docs/marketing/designs/
```

Do not add it without asking.

## Append protocol

When /design generates a new section:

1. Read `docs/marketing/designs/index.html`. If it does not exist, create it from the boilerplate above (after asking about `.gitignore` once, see above).
2. Locate the marker `<!-- DESIGNS_INSERT_HERE: ... -->`.
3. Insert the new `<section>` immediately AFTER the marker (so newest is on top).
4. Save the file.

Use `Edit` with `old_string` = the marker comment and `new_string` = the marker comment + `\n\n` + the new section. This guarantees correct positioning.

## Re-running an existing design with new data

If the user asks "rerun the X card with the new figures":
1. Find the section with the matching id pattern.
2. Copy its structure into a new section with today's date in the id.
3. Swap the data values (verify each against `src/data/fitness/`, the exercise database in `public/databases/`, the programme definition, or the figure Victor supplied).
4. Append; do not replace the old one (it is a record).

## Reset / archive

If the file grows past 50 sections, prompt the user about archiving older designs to `docs/marketing/designs/archive_YYYY_QN.html`. Do not auto-archive.
